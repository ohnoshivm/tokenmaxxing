# TOKENMAXXING 2.0 — Spec: "Yardstick + Fix"

Status: DRAFT for owner review · 2026-10-21 · base: `main` @ v1.5.0 (`b28cc49`)

## Goal

TOKENMAXXING exists to **save as much usage as possible while delivering the highest quality and quantity of work**. 1.5 measures usage only. 2.0 adds:

1. **The yardstick** — `audit` also measures *work delivered* and *rework*, so every change can be judged as "verified work per unit of usage".
2. **Fix** — `fix` turns doctor/audit findings into safe, reversible actions instead of a to-do list.
3. **Cache guard** — an opt-in hook that stops the single biggest measured waste (sending a prompt into a cold cache) before it happens.

Out of scope for 2.0 (planned): delegation audit + dispatcher, per-model quality gate (2.1); allowance portfolio, `uvx`/plugin packaging (2.2).

## Constraints (all features)

- Python ≥ 3.9, **stdlib only**, no new dependencies. Match the existing style in `scripts/*.py` (small functions, `add_arguments`/`run` pattern, `--json` output).
- Offline. Never upload anything. Never print transcript content, prompts, secrets or MCP env values.
- Never write `settings.json` or any auth/provider config. Never delete a file: only move, with a manifest and undo.
- Everything that is a heuristic is labelled as one in human output (`proxy`, `estimate`).
- Existing commands, flags and `--json` keys stay backward compatible; new keys are additive.
- All 58 existing tests keep passing; CI (3.9/3.12 × ubuntu/macos) green.

## Feature 1 — Work ledger in `audit` (the yardstick)

### What is counted (per session, Claude Code and Codex)

Parse tool calls and their results (Claude: `tool_use` + matching `tool_result` incl. `is_error`; Codex: function-call / `apply_patch` / shell exec events and their exit codes).

| Field | Definition |
| --- | --- |
| `edits` | Successful file-changing calls: `Edit`, `MultiEdit`, `Write`, `NotebookEdit`; Codex `apply_patch`. Failed calls (`is_error`) don't count. |
| `checks` | Shell calls whose command matches the check pattern (below). |
| `checks_passed` / `checks_failed` | By result: Claude `is_error` false/true (non-zero exit sets `is_error`); Codex exit code 0 / non-zero. Unknown outcome → not counted in either. |
| `commits` | Successful shell calls containing `git commit` (not `--dry-run`). |
| `verified_edit_sessions` | Sessions with ≥1 edit where a passing check ran **after the last edit**. |
| `unverified_edit_sessions` | Sessions with ≥1 edit and no passing check after the last edit. |
| `skills_used` | Counter of skill invocations by name, from **both** sources: Claude `Skill` tool calls (`input.skill`) **and** user slash-command invocations recorded in transcripts (user messages carrying a `<command-name>/name</command-name>` tag or equivalent). Keep the `plugin:` prefix as a separate field. Missing the slash-command source would make `fix` archive skills the user runs by hand — treat it as a blocking requirement with its own tests. |

Check pattern (one compiled regex in `audit.py`, tested): matches common test/build/lint/typecheck invocations, e.g. `pytest`, `python -m unittest`, `npm|pnpm|yarn|bun (run )?(test|build|lint|typecheck|check)`, `vitest`, `jest`, `tsc`, `eslint`, `ruff`, `mypy`, `cargo (test|build|check|clippy)`, `go (test|build|vet)`, `make (test|check|build)`, `gradle|mvn .*test`, `swift (test|build)`, `playwright test`. Match on the first command of each `&&`/`;`/`|` segment, not anywhere in the string (avoid `echo pytest`).

### Derived metrics (whole window)

- **Usage per passing check** = weighted cost units ÷ `checks_passed`. Headline efficiency number. Lower = better. It can be inflated by re-running the same check, so also count `distinct_passing_checks` (unique normalized command per session) and use that as the divisor; report both in `--json`.
- **Rework rate** = `checks_failed` ÷ (`checks_passed` + `checks_failed`). Lower = better.
- **Verified-edit share** = `verified_edit_sessions` ÷ (verified + unverified). Higher = better.
- **Premium share** = share of weighted usage on premium-tier models. Tier table lives in a new `policy/model-tiers.json` (pattern → `premium` | `standard` | `economy`), e.g. `opus` → premium, `sonnet` → standard, `haiku` → economy, `gpt-*-sol` → premium, `gpt-*-luna` → standard, `deepseek` / `flash` → economy. Unknown models → `unknown`, listed by name. Shown as information; labelled "lower usually = cheaper, check quality" — not auto-judged better/worse.

### Output

New block after the existing usage block:

```text
Work (proxy — counted from tool calls, not a quality judgement)
  edits 412 · checks 96 (81 passed, 15 failed) · commits 23
  rework rate 16% · verified-edit sessions 31/40 (78%)
  usage per passing check 5.5M units
  model mix: premium 78% · standard 15% · economy 7%
```

- `audit --compare`: add rows for usage per passing check (lower better), rework rate (lower better), verified-edit share (higher better), premium share (neutral). When either window has `< 5` passing checks, print `n/a (too few checks)` instead of a percentage.
- `--json`: add a `work` object with every raw count and derived metric, plus `skills_used`.
- Findings: add ranked findings when thresholds are hit, e.g. rework rate > 25% ("failed checks are being paid for twice — tighten briefs / run targeted tests first"); verified-edit share < 50% ("edits often end without a passing check"). Keep wording factual.

### Tests

Synthetic fixture transcripts (Claude + Codex) covering: successful/failed edit, passing/failing check, `echo pytest` non-match, check before vs after last edit, `git commit` success/failure, `Skill` calls with and without plugin prefix, unknown model tier, compare with too few checks.

## Feature 2 — `tokenmaxxing fix`

### CLI

```text
tokenmaxxing fix [--since 30d] [--config-dir PATH] [--keep NAME ...] [--apply] [--json]
tokenmaxxing fix --undo [RUN_ID]      # default: most recent run
tokenmaxxing fix --list               # list past runs from manifests
```

Default is a **dry run**: print the plan with estimated savings and change nothing. `--apply` executes only the auto-applicable actions.

### Actions

| Action | Auto-applied with `--apply`? | Rule |
| --- | --- | --- |
| **Archive unused user skills** | Yes | Skill dirs directly under `<config_dir>/skills/` (not plugin-provided, not project-level) with **zero** invocations in `audit` `skills_used` for the window. Requires the window to contain ≥ 10 Claude sessions; otherwise the action is skipped with the reason. `--keep` exempts names. A symlinked skill: move the link only, never its target. |
| **Archive duplicate skill copies** | Yes | Same skill name present twice under `<config_dir>/skills` (use doctor's `_duplicates`): archive the copy that is not the one Claude Code would load; if that can't be determined, don't auto-apply — suggest. |
| **Stacked optimizers** | No — suggest | Print the exact command(s) to disable all but one (e.g. `/plugin disable whittle`), and which profile maps to which. |
| **Oversized instruction files** | No — suggest | For each CLAUDE.md over the doctor threshold: list its largest sections by heading with token estimates, and suggest moving rarely-needed ones into a referenced file. |
| **Large MCP/plugin/hook overhead** | No — suggest | Reuse existing doctor findings. |

Each action line shows the estimated per-session token saving (doctor's estimates for skill metadata) and a total, labelled `estimate`.

### Archive + undo

- Moves go to `<config_dir>/tokenmaxxing-archive/<RUN_ID>/skills/<name>` where `RUN_ID` = UTC timestamp `YYYYMMDDTHHMMSSZ`.
- Write `<config_dir>/tokenmaxxing-archive/<RUN_ID>/manifest.json` **before** moving: `{run_id, version, created, config_dir, moves:[{src, dst, kind}]}`; then update each entry with `done: true` as it moves (a crash mid-run leaves an undoable manifest).
- `--undo`: move each `done` entry back; refuse an entry (and report it) if `src` already exists again; mark the manifest `undone`. Idempotent.
- After `--apply`, print: what moved, total estimated saving, the undo command, and "restart Claude Code sessions to pick up the change".

### Tests

Temp config dirs: dry run changes nothing; apply moves only unused skills; `--keep` honoured; < 10 sessions → skipped; symlink moved as link; manifest written before moves; undo restores; undo refuses conflicts; second undo is a no-op; `settings.json` byte-identical after every run.

## Feature 3 — Cache guard (opt-in hook)

Audit on the owner's machine found 138 cache rebuilds in 30 days, mostly after idling past the prompt-cache TTL. The guard stops that **before** the prompt is sent.

### CLI

```text
tokenmaxxing guard --print-hook          # print the settings.json snippet; never edits settings
tokenmaxxing guard --hook                # the hook entry point (reads hook JSON on stdin)
  [--min-context 50000] [--grace 120]
```

### Behaviour (`--hook`, registered as a `UserPromptSubmit` hook)

1. Read the hook payload from stdin; get `transcript_path` and the prompt text. Any parse error → exit 0 silently (the guard must never break a session).
2. Let prompts starting with `/` pass (slash commands such as `/compact`, `/clear`).
3. Reuse `statusline` transcript reading to get last assistant activity time, current context size and inferred cache TTL (5 min / 1 h).
4. If idle > TTL **and** context ≥ `--min-context`, and no guard marker for this session is newer than `--grace` seconds: write the marker, and **block once** using the hook's documented block mechanism, with a user-visible message such as:
   `Cache cold (idle 14m). Sending re-sends ~129k tokens. Re-send to continue, /compact to keep going lighter, or /clear for a new task.`
5. Otherwise (including a re-send within the grace period) → allow with no output.
6. Must add **zero** tokens to model context in the allow path, and must finish in < 200 ms on a 50 MB transcript (tail-read only, like statusline).
7. Marker files live in `<config_dir>/tokenmaxxing-guard/` keyed by session id; prune markers older than a day.

**Executor must verify the exact Claude Code hook contract** (stdin fields, how to block, how a message is shown to the user, whether slash commands trigger `UserPromptSubmit`) from the current official docs at https://docs.claude.com/en/docs/claude-code/hooks before implementing, and cite what was used in the PR description. If blocking-once is not possible, ship warn-only and say so.

### Tests

Payload fixtures: warm cache → allow; cold + small context → allow; cold + large context → block + marker; re-send within grace → allow; slash command → allow; malformed stdin → exit 0; missing transcript → exit 0; timing check on a large synthetic transcript.

## Acceptance criteria

1. `python3 -m unittest discover -s tests` passes; all new tests included; CI green on the PR.
2. `python3 tokenmaxxing.py --version` → `tokenmaxxing 2.0.0`.
3. On a real machine: `audit --since 30d` prints the Work block with non-zero counts; `audit --compare` shows the new rows; `--json` contains `work` and `skills_used`.
4. `fix` (dry run) lists archivable skills with estimates and changes nothing (verified by hashing the config dir before/after); `fix --apply` then `fix --undo` round-trips to an identical tree.
5. `guard --hook` behaves per the payload tests; `guard --print-hook` prints a snippet and writes nothing.
6. `settings.json` is never modified by any command.
